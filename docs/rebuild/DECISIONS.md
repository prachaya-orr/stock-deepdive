# Decision log

These decisions were agreed with the owner in a five-round design interview on 2026-11-01.
Each one is binding unless a later entry supersedes it. Format: **decision**, then the reason.

## Round 1: scope

| # | Decision | Reason |
|---|---|---|
| D1 | Deliver a spec set plus phased prompts, not one giant prompt | Long single prompts drift. Files in the repo can be reviewed and diffed |
| D2 | Executor is Claude Code (fresh session per phase) | Sub-agents are available, and the pipeline was already validated live on it |
| D3 | Evolve inside the fork. Reuse proven parts (docx embedded-table converter, iDisc fetcher) with tests | Those parts worked on DITTO and BGRIM. The broken parts (number layer, prompts) are rebuilt anyway |
| D4 | Claude Code only for v1. Keep a seam for Codex later | Dual-host support caused the `<ราก>`/`${CLAUDE_PLUGIN_ROOT}` churn and a stale `AGENTS.md` |
| D5 | Thai market first. Fetchers sit behind a source-adapter interface | The US path was never live-tested, and XBRL companyfacts is structurally different |
| D6 | Hybrid orchestration: scripts own the pipeline, agents do judgment only | Determinism where possible, without needing an API key |
| D7 | Outputs: offline HTML (dashboard + article), `model.xlsx`, `facts.jsonl`, `model.json` | Structured data exists anyway, so exporting it is nearly free |
| D8 | Code, specs and prompts in English. Article in Thai, language-switchable later | English prompts are cheaper and followed more precisely. Readers stay Thai |
| D9 | Add a dashboard with a football-field valuation chart | Owner request |

## Round 2: shape

| # | Decision | Reason |
|---|---|---|
| D10 | One HTML file with two tabs: **Dashboard** and **Article** | Stays single-file and offline. Both tabs render from the same `model.json`, so they cannot disagree |
| D11 | Market data comes from the TradingView MCP via an agent step that writes `market.json`. Fallback: user-supplied file. Everything is tier `secondary_market` with a date | Scripts cannot call MCP. The pipeline must still work without it |
| D12 | Dependencies via `uv` + `pyproject.toml` with pinned `openpyxl` and `pypdf` | Still zero manual install, reproducible versions. `uv 0.11.3` is present on the dev machine |
| D13 | Golden fixtures: commit converted text, xlsx and human-verified facts for BGRIM and DITTO. No PDFs | Offline CI. These are public filings |
| D14 | Specs live in `docs/rebuild/` on `feature/rebuild-spec`, with a PR into `develop` | Separates "what to build" from "what exists" |

## Round 3: valuation and extraction

| # | Decision | Reason |
|---|---|---|
| D15 | Default football-field bars: 52-week range, historical P/E band, historical P/BV band, peer EV/EBITDA, DCF (sensitivity range). Peer P/E and DDM are opt-in via config. A separate **reverse-DCF** box shows what the price implies | Covers market, relative and intrinsic views. Reverse DCF is the "what must you believe" frame |
| D16 | No analyst target prices in v1 | Putting them on the same chart reads as an answer, which conflicts with the no-advice rule |
| D17 | Valuation assumptions live in a per-ticker `assumptions.yaml` with defaults and sources. An agent may propose changes but must give a rationale. A script range-checks them, and the dashboard shows them all | Auditable, reproducible, and the user can edit one file and re-run |
| D18 | Peer set: an agent proposes it with reasons, stored in `assumptions.yaml` and reused afterwards. The user can edit it | Peer choice drives the EV/EBITDA bar. It must be stable across runs |
| D19 | Charts are SVG generated by Python. A tiny inline JS handles tabs and tooltips only | Deterministic, snapshot-testable, small, offline |
| D20 | **Primary statements (BS/IS/CF) are parsed from the xlsx by script.** Agents extract only notes and 56-1 items, with page or line citations | The main numbers never pass through an LLM. Agents keep the interpretive work |

## Round 4: data model and flow

| # | Decision | Reason |
|---|---|---|
| D21 | About 40 canonical line items, mapped through a synonym dictionary. Unmapped lines are kept as `raw` facts | Enough for every ratio. Company-specific lines (for example perpetual debentures) stay referenceable |
| D22 | Parser confidence comes from accounting identities and comparative cross-checks. On failure, an agent extracts that statement, flagged as `extraction: agent`, and the reason is recorded in the run manifest | Keeps the pipeline moving and turns failures into future test cases |
| D23 | Periods are `(start, end)`. Quarterly and TTM values are derived by subtraction, tagged `derived`, and point to their inputs | Thai filings are year-to-date. This also handles non-December fiscal years |
| D24 | Store both consolidated and separate figures. The model uses consolidated | Separate statements show parent-level cash for dividends and debt (relevant to the BGRIM finding of a 142% payout) |
| D25 | Keep 3 writer lanes (10 sections). Writers cite by ID only. A **critic** reviews the whole draft, with at most 1 revision loop. The strict number gate blocks delivery | The lanes proved fast. Critic and blocking gates were what the legacy plugin lacked |
| D26 | Phase plan P0–P7 as in [PHASES.md](PHASES.md) | Dependency order. Doing the dashboard first would require fake data |

## Round 5: process

| # | Decision | Reason |
|---|---|---|
| D27 | New plugin name `stock-deepdive-pro` (v0.x until P7, then 1.0.0), installable side by side with `lite` | Outputs and dependencies change a lot, so existing `lite` users must not break |
| D28 | One branch `feature/pN-…` and one PR into `develop` per phase. A human merges | Reviewable, revertible units |
| D29 | `plugins/stock-deepdive-lite/` is untouched. The new plugin is added to the same marketplaces | Allows A/B runs on the same ticker |
| D30 | Work stays in the fork. Upstream PRs (for example legacy bug fixes) are a separate later decision. Keep the MIT notice | Contributing to someone else's repo is an outward action that deserves its own decision |
